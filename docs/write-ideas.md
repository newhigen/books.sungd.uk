# 별점·책 추가를 어디에 쓸까 (아직 안 붙임)

지금 이 페이지는 읽기만 한다. 폰에서 별점을 매기거나 산 책을 바로 추가하려면 그 값을
**어딘가에 저장**해야 하는데, 정적 페이지 자체에는 저장할 곳이 없다. 길은 셋이다.

## 1. GitHub 에 바로 커밋

페이지에서 별점을 매기면 자바스크립트가 GitHub API 로 `sources/*.json` 을 고쳐 커밋한다.

- 서버가 필요 없다. 데이터가 repo 안에 남아 기록도 따라온다.
- 폰에서 한 것이 맥에도 보인다.
- 화면은 즉시 바꾸고 커밋은 뒤에서 — 실제 사이트 반영은 Pages 재배포까지 1~2분.
- 이 repo 에만 쓸 수 있는 토큰(fine-grained, contents:write)을 브라우저에 한 번 저장한다.
  토큰이 새어도 이 repo 말고는 손댈 수 없게 범위를 좁힌다.
- 쓰기 UI 는 남에게 안 보이게 숨은 주소(`#!write` 같은)에 둔다. 공개 페이지라 별점 자체는 공개.

## 2. 내 기기에만 저장 (localStorage)

브라우저 저장소에 넣는다. 코드 몇 줄, 즉시 반영.

- 폰에서 매긴 별점이 맥에는 안 뜬다. 브라우저 데이터를 지우면 사라진다.
- 임시로 써 보다가 1번이나 3번으로 옮기기는 쉽다 — 내보내기 버튼 하나면 된다.

## 3. 작은 서버 하나 (Cloudflare Worker + KV)

**Cloudflare Worker** 는 클라우드플레어가 세계 곳곳에 둔 서버에서 도는 작은 프로그램이다.
서버를 사거나 켜 둘 필요 없이, 주소로 요청이 오는 순간에만 코드가 돌고 답을 준다.
**KV** 는 거기 딸린 간단한 저장소(열쇠-값)다. 별점 같은 걸 넣어두기에 맞다.

- 즉시 반영되고 기기끼리 같은 데이터를 본다. 셋 중 제일 매끄럽다.
- 무료 범위가 개인 책장에는 한참 남는다 (요청 하루 10만, KV 쓰기 하루 1천 선).
  정확한 한도는 바뀌니 붙일 때 https://developers.cloudflare.com/workers/platform/limits 확인.
- 대신 관리할 것이 하나 는다. 지금 sungd.uk 은 전부 GitHub Pages 라 여기만 결이 달라진다.

## 지금 생각

**1번(GitHub 에 커밋)이 이 사이트와 결이 같다.** 데이터가 이미 repo 안 JSON 이고, 서버가
늘지 않고, 기록이 남는다. 1~2분 지연은 별점·책 추가에는 걸리지 않는다.

붙일 때 같이 정할 것:

- 별점 척도 — 5단계보다 3단계(좋음·보통·별로)가 덜 자의적이다.
- 산 책 추가 — 제목만 넣으면 `enrich.py` 와 같은 방식으로 표지·저자를 찾아 채운다.
- 대여 — 도서관 책은 소장이 아니니 `sources` 에 `library` 를 두고 반납일을 같이 적는다.
- 읽는 중 표시 — 지금은 읽음/아직 둘뿐이다.
